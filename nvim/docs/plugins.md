# Plugin inventory

The inventory comes from [`lua/plugins/spec.lua`](../.config/nvim/lua/plugins/spec.lua) and
[`nvim-pack-lock.json`](../.config/nvim/nvim-pack-lock.json). It currently contains 47 repositories:
25 eager specs and 22 optional specs. “Eager” means registered with `vim.pack.add(eager)` at
startup; “optional” means registered with a no-op load callback, then activated with `:packadd` by a
lazy group. All revision IDs are in the lock file; branch/tag constraints are noted below. See
[the dated review](review.md) for the local revision comparison and verification limits. Optional
config files that own global mappings register them at startup; their setup runs when the group is
first loaded.
The recommendation labels below describe the current workflow; no package change is proposed in
this audit. A dependency library inherits the decision for the feature that uses it.

## Requirements and load behavior

The configuration requires Neovim 0.12+ and Git for `vim.pack`. `vim.pack` is
[experimental](https://neovim.io/doc/user/pack/) and uses the installed checkout when it is already
present; an existing checkout can therefore differ from the committed lock revision until it is
explicitly synchronized. `blink.cmp` follows `main` (v2), needs Neovim 0.12+ and `blink.lib`, and
[upstream warns about breaking changes](https://github.com/Saghen/blink.cmp). Its Rust matcher can
be built with Cargo; this config selects Lua matching if the native library is unavailable.
`friendly-snippets` is snippet data for Blink; `mini.icons` supplies completion-kind, file, and
directory icons. `mini.extra` supplies the configured
additional MiniPick sources. The configured MiniPick file and grep pickers work best with `rg`.

Tree-sitter is correctly eager: its [current main-branch instructions](https://github.com/nvim-treesitter/nvim-treesitter/blob/main/README.md)
do not support lazy loading. Parser installation and updates also need `tree-sitter-cli` 0.26.1+,
`tar`, `curl`, and a C compiler. Installed parsers must be updated with the plugin's queries.
Oil is eager because it handles directory buffers; its [requirements](https://github.com/stevearc/oil.nvim)
are Neovim 0.10+ and only an optional icon provider. Conform needs Neovim 0.10+; its configured
formatters are `stylua`, `clang-format`, `gersemi`, and `ruff`, with LSP fallback. The `filter`
fields in the CMake/Python filetype tables are supported Conform options and exclude the named LSP
clients from that fallback. Automatic format on save is disabled.

The `buffer_ui` group loads on the first `BufReadPre` or `BufNewFile`, or on a relevant lazy mapping.
Its packages load together, so invoking `<Space>ast` or `<Space>vw` also loads the other buffer UI
packages. The other optional groups load on their first mapped use; LSP preview/action/usage maps
exist only after LSP attach. `nvim-dap-ui` [requires](https://github.com/rcarriga/nvim-dap-ui)
`nvim-dap` and `nvim-nio`; the whole DAP group loads on the first `<Space>d...` mapping. A debug
session additionally needs a CodeLLDB executable. Harpoon and Spectre use `plenary.nvim`; Spectre
uses configured `rg` and `sd` executables, with [upstream caution](https://github.com/nvim-pack/nvim-spectre)
that project replacement does not have direct undo. `goto-preview` uses `logger.nvim` and the
already loaded MiniPick provider. Floaterm [uses Volt](https://github.com/nvzone/floaterm) for its
UI. These libraries have no independent user-facing workflow here.

## Workflow comparisons and decisions

| Workflow | Current choice and benefit | Simpler or alternative choice | Decision and migration cost |
| --- | --- | --- | --- |
| Buffer switching | MiniPick `<Space>pb` is a general fuzzy picker; Snipe `<Space>sn` provides persistent single-key hints and menu actions. | Use [MiniPick buffers](https://github.com/nvim-mini/mini.pick) alone. | **Simplify Snipe** if hints are not used; one mapping and one lazy spec disappear, but its tag-driven navigation is lost. |
| Colored indent guides | IBL renders guides and recreates the four 7% blended colors in a highlight hook. | [IBL accepts multiple highlight groups directly](https://github.com/lukas-reineke/indent-blankline.nvim). | Rainbowline was removed after the highlight values matched before and after a colorscheme reload. |
| Completion icons | Blink uses MiniIcons for LSP kinds and paths. | [MiniIcons has LSP kind icons](https://github.com/nvim-mini/mini.icons). | Lspkind was removed; Blink kind highlights and path icon behavior remain. |
| Width marker | `colorcolumn=120` is always visible; Smartcolumn adds contextual EditorConfig behavior. | Keep one width policy. | **Simplify Smartcolumn** only if the contextual behavior is not useful; otherwise keep it and reconsider the fixed column. |
| Floating terminal | Floaterm plus Volt gives a toggleable float, sidebar, and terminal list. | Built-in `:terminal` and the configured split/tab mappings cover simple shells. | **Consider replacement** if the floating UI is not used. Migration loses its session UI but removes two repositories and the fragile `FloatermClose` integration. |
| Project replace | Spectre offers a searchable review panel with `rg`/`sd`. | `:vimgrep`, quickfix, and `:cfdo` use built-in commands. | **Keep Spectre** for deliberate multi-file replacements; the built-in route is simpler for rare edits but lacks Spectre's panel. Review changes before writing either way. |
| File browsing | Oil edits directories as buffers, supports splits/floats, and is the default explorer. | Built-in netrw has no added repository; [MiniFiles](https://github.com/nvim-mini/mini.files) offers a column view and editable directory buffers. | **Keep Oil** because replacing its mappings and directory editing workflow costs more than it saves. MiniFiles is a different UI, and its upstream notes no macOS/Windows guarantee. |

## Dependencies and removals

Transitive relationships represented explicitly by groups include `volt` → Floaterm, `plenary.nvim`
→ Harpoon and Spectre, `logger.nvim` → goto-preview, and `nvim-nio`/`nvim-dap` → DAP UI. Blink uses
`blink.lib`, `friendly-snippets`, and `mini.icons`; MiniPick uses MiniExtra. External binaries
include language servers, formatters, ripgrep, sd, Tree-sitter CLI/parser downloads, and CodeLLDB.
The config checks these executables on first use. Missing formatters retain Conform's LSP fallback;
Actions Preview uses plain diffs without `diff-so-fancy`.

Neo-tree and `nui.nvim`, Vague, `nvim-web-devicons`, Hardtime, the forked MiniPick package, the
commented trailing-whitespace plugin, and plain LLDB adapter configuration were removed. Oil,
Kanagawa, MiniIcons, upstream MiniPick/MiniTrailspace, CodeLLDB, and upstream Tree-sitter are the
current counterparts where applicable.

## Native package references

Neovim's [`vim.pack` help](https://neovim.io/doc/user/pack.html) describes the package manager and
`vim.pack.update()` workflow. Evgeni Chasnovski's
[vim.pack guide](https://echasnovski.com/blog/2026-03-13-a-guide-to-vim-pack) is an additional
practical reference. `vim.pack` installs/updates packages and adds them to the runtime path; the
local lazy helper determines when optional groups are activated.
