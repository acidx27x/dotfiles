# Neovim plugin inventory

This inventory covers all **50 repositories** in `nvim-pack-lock.json`, plus configured but inactive
modules. Repository revisions were compared with the installed package checkouts on 2026-10-25 and
matched the lockfile.

## Loading legend

- **Eager/setup**: `vim.pack.add()` runs during `init.lua`, followed by `require(...).setup()` or
  equivalent initialization.
- **Eager/runtime**: the package is added during init and its runtime files are sourced, but local
  code does not call a setup function directly.
- **Dependency**: explicitly added for another plugin. It is still active at startup.
- **Registered**: setup registers autocommands, LSP servers, or adapters early; the external process
  or feature starts later.
- **Inactive**: a config file exists but its `require()` is commented out.

There are no native key, command, event, or filetype lazy-loading triggers today. `vim.pack`'s first
call also reconciles the checked-in lockfile, but each setup module still activates its package and
loads Lua synchronously.

## Update behavior

The lockfile pins exact revisions even when specs track a branch or version range. The notable
tracking constraints are:

- Blink: `version = "v1"`.
- Harpoon: `version = "harpoon2"`.
- nvim-treesitter: `version = "master"`.

Review updates interactively with `:packupdate` (or `:lua vim.pack.update()`), write the
confirmation buffer to apply them, restart Neovim, then run `:checkhealth`. Tree-sitter parser
updates are a separate compatibility operation and must accompany the branch migration.
